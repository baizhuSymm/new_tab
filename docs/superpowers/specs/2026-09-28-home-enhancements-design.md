# 首页效率组件增强规格

- 日期：2026-09-28
- 状态：待用户审阅
- 基础规格：`2026-09-26-personal-new-tab-design.md`
- 视觉方向：用户选择第一版视觉风格，并明确首页固定为左侧网站管理/最近打开，右侧日程/待办/快速记录。

## 1. 目标与边界

在现有个人新标签页上增加轻量日程与个性化能力，让用户打开首页即可管理安排，并按个人习惯整理首页。继续使用现有 React + TypeScript + Vite、CSS Modules 和本地存储架构。

本规格是第一版规格的增量，不取代其中已有的搜索、OpenClaw入口、快捷网站、待办、便签、天气和最近打开行为。

明确范围：

- 日程以具体日期、开始/结束时间和标题/描述管理；不制作日历组件、日期网格或月历视图。
- 保留现有唯一的 OpenClaw 入口；不增加其它 AI 工具入口，也不改变 OpenClaw 连接方式。
- 不制作计算器；日程、快捷网站、待办和便签均为本地功能，不要求账号、后端或云同步。
- 不做在线组件商店、远程壁纸服务、系统通知或日历账户同步。

## 2. 视觉与首页结构

![首页增强方向：无日历，网站分组使用页签](./assets/home-enhancements-concept.png)

沿用既有首页视觉基准：窄侧栏、城市壁纸与时间天气、搜索栏、紧凑 OpenClaw 入口、白底与绿色强调色。图片用于表达布局，不代表图片中的示例事件、站点内容需要照搬。

- 搜索栏下方仍仅显示现有 OpenClaw 入口；对话区按现状点击后展开。
- 主体固定为左右两栏。左栏依次放网站管理和最近打开；右栏依次放日程管理、待办、快速记录。
- 日程管理直接显示近期安排列表；不出现月历、倒数/纪念日清单或计算器。
- 网站分组控件改为网站标题下方、网站图标上方的横向 Tab；活动分组有清晰选中态，Tab 紧邻对应网站图标网格。
- 保持当前紧凑间距原则，避免新增功能把首屏挤成卡片墙。具体断点与组件尺寸在实施计划中核对现有响应式布局后确定。

## 3. 功能与交互

### 3.1 日程管理

- 首页列表显示近期的日程安排；支持新增、编辑、删除和按开始时间排序。
- 每项包含标题、开始日期与时间、可选结束时间、可选描述及颜色标识。日期和时间按用户本地时区录入和展示。
- 支持查看全部日程；已结束安排可在完整管理视图中查看，不混入首页近期列表。
- 日程编辑使用简单表单输入具体日期和时间，不呈现月历组件。
- 空列表提供直接新增入口；删除有确认或可撤销反馈。
- 不创建系统闹钟、不发送通知、不连接 Google/Outlook 等外部日历，也不做倒数或周年重复计算。

### 3.3 主题与壁纸库

- 提供浅色和深色主题；颜色通过现有 CSS Variables 统一切换，并保留站点图标的原始品牌色。
- 壁纸选择面板区分内置壁纸与用户本地上传壁纸；可选择、预览并调整裁切位置。
- 用户上传的壁纸保存在本地；错误格式、尺寸过大、压缩失败或存储空间不足时提示原因，并保留当前正在使用的壁纸。
- 原有城市壁纸和单张自定义壁纸数据通过迁移保留，不因升级丢失。
- 不加载远程壁纸推荐，不增加天气以外的网络请求。

### 3.3 组件中心与布局

- 提供清楚的“添加小组件/管理组件”入口，列出可用组件和当前显示状态。
- 可选组件包括网站管理、最近打开、日程管理、待办和快速记录。
- 支持组件显隐和栏内拖动排序；网站管理与最近打开固定在左栏，日程、待办和快速记录固定在右栏，不支持跨栏移动；提供键盘可操作的排序控制。
- 编辑状态可保存或取消；取消恢复进入编辑前布局。恢复默认布局仅重置布局，不删除业务数据。
- 搜索栏、壁纸/时间天气和 OpenClaw 入口不纳入组件中心。
- 不支持任意坐标定位、重叠、嵌套组件或用户编写组件。

### 3.4 网站分组 Tab

- Tab 名称来自现有 `ShortcutGroup`，顺序沿用分组排序；切换只过滤当前快捷网站，不修改分组或站点数据。
- 活动分组默认沿用现有首页选择逻辑；本阶段不要求跨刷新记住最后选中的分组。
- 编辑模式中的新增、重命名、删除分组和站点移动行为继续有效，入口仍在网站区管理控件中。
- 窄屏横向空间不足时，Tab 可横向滚动且保持触控和键盘可用，不造成页面横向溢出。
- 使用语义化 Tab 交互：可访问名称、选中状态、键盘切换和正确的焦点管理。

## 4. 数据与兼容

新增本地实体：

- `ScheduleEvent`：稳定 id、标题、开始时间、可选结束时间、可选描述、排序值及更新时间。时间以 ISO 格式保存，并按用户本地时区展示。
- 设置新增主题标识；壁纸记录扩展为可保存多个本地资产并关联当前选中项。
- 布局模块标识增加日程管理，并迁移为左/右两栏固定归属及栏内顺序。

兼容要求：

- 迁移幂等；不得清空或覆盖现有网站、分组、待办、便签、壁纸及布局。
- 旧布局中的未知或新增模块应安全回退到可用默认布局，并保留可迁移的旧数据。
- 继续遵循第一版按实体独立保存的原则，更新日期列表或主题不得覆盖其它数据。
- 普通网页预览与扩展的存储适配行为保持一致，数据仍彼此独立。

## 5. 验收标准

1. 首页无月历组件/网格、倒数/纪念日清单和计算器；可新增、编辑和删除含具体日期与时间的日程。
2. 首页固定为左侧网站管理+最近打开，右侧日程管理+待办+快速记录；组件可以隐藏或在所属栏内排序，不会跨栏。
3. 网站分组为横向页签；切换分组、维护分组、移动网站、拖拽网站及窄屏键盘操作均正常。
4. 主题切换后刷新仍生效；切换壁纸不会丢失旧的自定义壁纸或改变裁切设置，存储失败时保留当前选择。
5. 组件布局保存、取消、恢复默认语义正确，布局重置不影响日程和其它业务数据。
6. 原有 OpenClaw、搜索、天气、待办和便签流程无回归；不出现额外 AI 工具或未经请求的外部服务。
7. 在 1440×1024、1024×768、390×844 和 320px 宽度验证首屏层级、内容密度、Tab 可用性、组件溢出与页面横向滚动。
8. 覆盖数据迁移、日程排序与时间边界、布局保存与取消、主题/壁纸选择和快捷网站分组的自动化测试，并通过类型检查与生产构建。

## 6. 明确不做

- 日历组件、月历网格、倒数/纪念日、第三方日历同步。
- 计算器和计算历史。
- 多 AI 工具目录或在此规格中实现 OpenClaw 对话连接。
- 云同步、账号、后端、在线壁纸库、组件市场和系统提醒。
- 高级日程提醒、重复日程、时区转换和任意数学脚本。

## 7. 后续阶段

本规格通过用户审阅后，再编写分步实施计划并确认执行方式；之后才进入代码实现。实施时先核对存储迁移、布局模块注册和响应式规则，再分别实现与测试各组件。
